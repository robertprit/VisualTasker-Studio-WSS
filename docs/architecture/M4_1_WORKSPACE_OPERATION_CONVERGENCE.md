# M4-1 Canonical WorkspaceOperation Convergence

## Scope

M4-1 converges existing BlockEditor and WSS FlowEditor semantic commands on the same
`WorkspaceOperationExecutor` already used by TextEditor source apply. It introduces no language,
runtime, provider, UI, function, subworkflow, variable-scope, or Workspace Explorer feature.

## Inventory

| Editor | User action | Previous path | Canonical target path | Migration |
| --- | --- | --- | --- | --- |
| Text | Apply EMScript draft | Apply guard -> semantic source plan -> transaction | `WorkspaceOperationExecutor.executeWithStagedPayload` | Already canonical; unchanged |
| Block | Create/palette/duplicate | Controller -> `WorkspaceAction` -> legacy reducer publication | `WorkspaceActionOperationAdapter` -> one transaction -> executor | Migrated |
| Block | Connect/detach/reorder stack | Drag controller -> reducer/canonical mutator | Adapter-created relation operations -> executor | Migrated |
| Block | Field/property edit | `WorkspaceAction.UpdateField` | `SetProperty` -> executor with shared schema | Migrated |
| Block | Type/branch shape replacement | `ReplaceBlockShape` -> reducer publication | relation operations plus `ReplaceEntityPayload` -> executor | Migrated |
| Block | Delete | reducer/canonical mutator | remove-relation/delete-entity operations -> executor | Migrated |
| Block | Create variable plus reporter | two separately published actions | `reduceAll` -> one transaction/revision | Migrated |
| Flow | Add node plus initial fields/optional sequence | multiple reducer publications | `reduceAll` -> one transaction/revision | Migrated |
| Flow | Connect/disconnect | facade -> reducer/canonical mutator | relation operations -> executor | Migrated |
| Flow | Replace occupied data input | disconnect then connect in two revisions | one `reduceAll` transaction | Migrated |
| Flow | Property/type/branch/delete | facade -> reducer publication | typed operation plan -> executor | Migrated |
| Block/Flow | Root position, collapse, FlowView sync | workspace/view payload update | projection-only publication without canonical revision | Classified, no semantic operation |
| Block | Undo/redo | validated `WorkspaceState` snapshots | restores previously accepted canonical transaction snapshot | Preserved; cross-editor matrix remains M4-2 |

Selection, focus, viewport pan/zoom, minimap state, routes, facets, and layout are projection state and
do not create a canonical transaction.

## Canonical Boundary

```text
Text source apply -------------------------+
                                            |
Block WorkspaceAction -> candidate plan ----+-> WorkspaceTransaction
                                            |          |
Flow mutation facade -> candidate plan -----+          v
                                           WorkspaceOperationExecutor
                                                      |
                                                      v
                                           CanonicalWorkspaceDocument
```

`WorkspaceAction` remains source compatible because it is used throughout BlockEditor interaction
code and fixtures. `WorkspaceReducer` is now a thin delegating adapter. The old reducer may construct
a local validated candidate, but it cannot publish that candidate: the adapter diffs canonical
entities/relations, creates deterministic typed operations, and delegates publication, revision and
rollback to the executor.

`ReplaceEntityPayload` covers semantic staged payload changes such as a compatible block type/shape
replacement which cannot be expressed as a scalar field property. It requires a changed staged
payload and a stable existing semantic owner; direct use without such a payload is rejected.

Native relation IDs are derived from semantic endpoints, kind and role, never from order, pixels,
render order or random UUIDs. Repeating an equal editor command against equal input therefore yields
the same relation identity and document.

## Invariants

1. Entity, relation and surviving branch IDs remain stable.
2. One logical compound command uses one transaction and advances one revision.
3. Failure returns the complete original document and revision.
4. Shared property schema and canonical validation remain mandatory.
5. Unknown metadata and unrelated fields survive staged publication.
6. Source anchors are ordinary retained metadata and are not regenerated by editor mutation.
7. Projection-only changes do not advance the canonical revision.
8. The adapter has no independent publication or history store.
9. No single-root, whole-project-script, copied-function, or script-local-only variable assumption was added.

  three-run determinism.

## Remaining Limits

- Undo/redo is snapshot based. It restores accepted canonical states correctly, but a central
  Text/Block/Flow undo-selection matrix remains M4-2.
- Reorder, detach and reconnect have module coverage; the complete cross-editor matrix remains M4-2.
- `CanonicalWorkspaceDocument` deliberately permits multiple roots. Functions, subworkflows and
  project-wide bindings require later explicit contracts and were not preimplemented here.
- Unsupported language families remain rejected before publication.
